# Схема событий

## Файл

- `movie_event.avsc` — Avro-схема события `movie-events` (namespace `cinema.analytics`, запись `MovieEvent`)

## Регистрация в Schema Registry

Схема автоматически регистрируется сервисом `producer` при старте (см. `producer/schema_bootstrap.py`)
Subject: `movie-events-value`, compatibility по умолчанию — BACKWARD. Версия 1.

## Выбор ключа партиционирования

В качестве ключа партиционирования выбран **`user_id`**.

**Обоснование:**

1. Все бизнес-метрики (DAU, retention, конверсия просмотра) считаются в разрезе пользователя -
   события одного пользователя должны обрабатываться упорядоченно (`VIEW_STARTED` должен предшествовать `VIEW_FINISHED`).
2. Партиционирование по `user_id` гарантирует, что все события одной пользовательской сессии
   попадут в одну партицию и сохранят порядок.
3. Нагрузка равномерно распределяется: активных пользователей много, «горячих» фильмов мало
   (партиционирование по `movie_id` приводит к перекосу — популярный фильм перегружал бы одну партицию).

## Топик

- Имя: `movie-events`
- Партиций: **3**
- `replication.factor = 2`, `min.insync.replicas = 1` (см. задание блока 8).

Создаётся автоматически сервисом `producer` при старте (через `AdminClient`).
